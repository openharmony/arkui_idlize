# Библиотека `prettier_formatter`

Эта библиотека предоставляет минимальную обёртку над `prettier/standalone`, настроенную на форматирование исходных файлов TypeScript и TSX в рамках проекта.

## Назначение

- Единообразное форматирование TS/TSX-фрагментов без привязки к глобальной конфигурации репозитория.
- Возможность подключения к собственным пайплайнам (например, в анализаторах или CLI), не затрагивая основной набор форматтеров.
- Точка расширения для экспериментов с альтернативными движками форматирования.

> ⚠️ **Важно.** Эта библиотека разработана как потенциальная альтернатива на будущее. В текущем решении она служит лёгкой прослойкой, не заменяющей полностью существующие механизмы форматирования (enhanced AST и т.п.).

## Ограничения

- Поддерживаются только файлы с расширениями `.ts` и `.tsx`.
- Поддержка ArkTS (ETS) отсутствует — обработка таких файлов осуществляется основными инструментами проекта.
- Предполагается, что конфигурация Prettier хранится локально (`libs/prettier_formatter/.prettierrc`) и не конфликтует с внешними настройками.

## Тестирование

### Быстрый запуск

Перейдите в каталог `libs/prettier_formatter` и запустите:

```bash
cd libs/prettier_formatter
npm test -- tests/prettier-based.test.ts
```

Также можно воспользоваться вспомогательным скриптом, оборачивающим тот же запуск:

```bash
cd libs/prettier_formatter
./run_prettier_test.sh
```

Тесты используют фикстуры внутри `tests/fixtures`. Для обновления эталонных `output.*` используйте утилиту из раздела ниже.

### Полезная утилита

Инструменты находятся в каталоге `tools/prettier_formatter` (подробности — в README внутри каталога). Основной CLI-скрипт `format-file.ts` принимает путь до файла и выводит отформатированную версию в STDOUT. Это упрощает обновление фикстур и одноразовое использование библиотеки:

```bash
cd <корень репозитория>
npx ts-node tools/prettier_formatter/format-file.ts --file path/to/file.tsx > formatted.tsx
```

Советы по работе со скриптом:

- Запускайте его из корня репозитория (`ts-node` подтянет локальные зависимости).
- При необходимости можно добавить `--transpile-only`, чтобы игнорировать строгие проверки типов во время отладки скрипта.
- Результат можно сразу вставлять в `fixtures/.../output.*`, либо использовать для диффа с `input.*`.
- По умолчанию утилита не падает на синтаксических ошибках и возвращает исходный текст как есть. Чтобы включить прежнее строгое поведение, используйте флаг `--strict`.
- Доступные ключи CLI: `--file <path>` (обязательный) и `--strict` (строгий режим, при ошибке парсинга выбрасывает исключение вместо возврата исходника).
- Скрипт `run_format-file.sh` (в `tools/prettier_formatter`) форматирует встроенную фикстуру. Запускайте его из этого каталога: `cd tools/prettier_formatter && ./run_format-file.sh [--strict]`.
- За дополнительными примерами и сценариями обращайтесь к `tools/prettier_formatter/README_RU.md`.

## Использование в коде

```ts
import { formatTypeScript, formatTsx, formatSourceCode } from 'libs/prettier_formatter';

const formatted = await formatTypeScript(sourceCode);
```

Дополнительные опции (например, путь до конфигурации или переопределение настроек) можно передавать через аргументы `formatSourceCode`/`formatTypeScript`/`formatTsx`.
Также можно управлять обработкой ошибок разбора через опцию `strictParsing` и реагировать на них, используя колбэк `onFormattingError`.
